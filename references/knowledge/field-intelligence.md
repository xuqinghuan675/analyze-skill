# V6 多源研究规程：信息差不是信息数量
本规程与 G0–G7、六域联动共用；不另造自评通关。source_registry.json 是导航与学习记录，不是研究任务中的事实数据库。source-atlas.md 为人工阅读索引。

## 五类重点来源如何分工
| 渠道 | 最有价值的用法 | 必查下一层 | 不得做 |
|---|---|---|---|
| X | 新公告、专业人士指出的异常、反方、市场关注点、时点线索 | 原帖时间、身份、完整上下文、外链原件、事件前后事实 | 将转发数当正确率；将截图/匿名爆料当已证实事实 |
| YouTube | 系统学习技术、金融、商业机制；发现研究问题 | 字幕时间段、术语、图表引用原始出处、实际数据与条件 | 只看标题就声称理解；没取得字幕就冒充观看 |
| 博客/长文/播客 | 提取假设、因果结构、对立解释、专业指标 | 模型原公式、数据来源、样本和发布日期、反例 | 把作者观点升级为真实因果或收益承诺 |
| 官方信/备忘录 | 研究资金配置、激励、承诺与实际兑现；分析决策方法 | 会计附注、管理层历史承诺、资本变动、后续原件 | 把名人偏好、持仓或信件当买入指令 |
| GitHub | 公开公式、数据清洗、仿真与识别方法、复现实验 | 版本/commit、许可、测试、数据输入、执行假设与适用范围 | 直接运行陌生脚本、自动填入密钥、把README收益当样本外成绩 |

## G0/G1：建立检索计划
先用 scripts/source_plan.py 按主要研究入口和主题选专项手册，人工确定哪些来源具有实质关系。搜索中文与原文语言；同时搜索支持/反对词（risk、failure、delay、competition、margin deterioration、修订、反例等）。检索应围绕问题与指标，不能为了凑 X/视频/博客/GitHub 配额查询无关内容。直接查公司、监管、统计与交易所，再用相应媒体寻找漏掉的机制、客户/供应商及反例。必要时使用原始行业标准、技术论文和公开课程。
每条重要线索另存 sources/lead_log.jsonl（不要求把所有零碎搜索记入），字段建议：lead_id, channel, author, url, original_time, observed_at, claim, entity, linked_primary_url, conflict_or_interest, status, next_question, evidence_refs, impact。status=unverified/linked/contradicted/unavailable；linked 必须已有实际可定位 E；保留无法访问的原因。作者是否专业、是否官方、是否一手要按主张判断。官方 X 是发言/公告的原件，但不能因此证明其预测真实，采访中的公司宣传也不等于实际销量。独立性按原始出处分组，不按转发媒体数量。截点之前可获得的信息与未来修订、事后复盘严格分开。
 
## X 专项（只读公开资料）
1. 识别身份：从作者官网/机构官方链接反查账号；核查用户名、机构、原帖ID与时间。蓝标、粉丝量、同名号不是独立证据。关键消息找首发并区分报道、转述、观点、推测与官方公告。不得把无法访问的付费/锁定内容视为已阅读。
2. 研究消息链：先抽取主体、动作、数量、条件、期限，再查直接影响对象、合同及物理/制度约束。找新闻前可用的预期和价格，区分事件首次曝光、正式公告、执行与结果。未核实消息只能作为情景；速度不能替代核实。
3. 例：X01 Damodaran 的国别风险更新→B03原文及数据→确认地区风险暴露/货币→改变折现率/现金流参数；不能直接使用历史风险溢价。X02 Javier Blas 的项目延期评论→项目方/许可/工程进度→可交付供给与投产时间→企业销量/价格/利润；不能把旧预测当已投产事实。X04 Kaiko 份额图→定义/场所覆盖/原始成交→同口径流动性/成本→价格影响假设；不能由市场份额直接推出投资方向。X03 央行官方会议→官方正文→政策阶段→实际执行量与预期差。
4. 搜索反方及利益关系，保留纠正/删改时间；不得用社交热度自动填胜率和投资概率，不自动发帖、点赞、关注、交易或访问未经授权的账户。
 
## YouTube、博客与信件专项
使用 references/video/fetch_captions.py 与 caption-workflow.md 直接获取人工/已有自动字幕。记录 video_id、语言、字幕来源、实际阅读的开始结束时间；将关键机制改写为自己的知识卡，链接原文时间点。自动字幕的术语、数值尤其要核对。没有字幕时可查作者公开讲义或正式文字稿；未另行授权不下载音频/运行ASR。长文与官方信只摘与问题相关的有限内容并标明位置、日期、事实/观点；不整篇照搬，不承诺已看完未读材料。
以“知识卡→本任务假设→独立取证→模型变量→反证”利用专家方法。遇到高质量论点问：实际指标是什么？前提是什么？竞争解释是什么？什么证据能推翻？如何进计算？若仅能写名言，不能作为研究成果。
 
## GitHub 专项
先确认官方作者链接、项目状态、LICENSE、release/commit、核心模块、tests、issues、数据许可；读代码而非只看 stars。隔离环境、最小依赖、不携带秘密，先用合成测试与小型公开数据复现关键功能；安装、运行、性能结果均须按实际情况记录。禁止用下载、仓库热度、默认样例通过冒充策略实盘优势。候选项目未经测试只列作候选。量化尤其核对时间对齐、交易成本、样本外、队列、强平及容量，按 empirical-research.md 和 risk-market-microstructure.md 验证。
 
## G2–G7 回流
G2 每张活跃域指标卡必须定义、公式/条件、解释、数据来源及反方；专业手册仅提供方法。G3 从线索生成可检验假设。G4 至少两层实际查证且六条联动均有两端原件或缺口。G5 每条能量化的联动由源数据进入计算，而非仅引用作者观点。G6 核查来源独立性、时间、原件与最强反证。G7 交付原始证据、计算、何时更新和风险。信源不可得就记录真实缺口并 PARTIAL，不以多份二手摘要抵消。
