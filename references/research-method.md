
# ANALYZE V6 完整研究方法

## 执行细则

本 Skill 的研究工作流必须执行，不是建议清单。启动研究前先读同目录 WORKFLOW.md、WORKFLOW_SCHEMA.md、AGENTS.md 、references/cross-domain.md 和对应研究手册。使用 scripts/research_gate.py 实际创建任务、保存各关成果、推进验收；禁止只读本文件后直接写报告。

在 项目根目录 执行（--routes 为主要入口，自动扩展六域）：

    python scripts\research_gate.py init 20261125-example --routes company
    python scripts\research_gate.py status 20261125-example
    python scripts\research_gate.py advance 20261125-example

已有任务先 status，不重复 init。依次执行 G0 契约 → G1 原始证据 → G2 指标解码 → G3 假设与竞争解释 → G4 穿透调查 → G5 模型与情景 → G6 反证 → G7 决策与交付。每关根据下一文件模板完成实质研究，再调用 advance；禁止跳关、伪造回执、用占位符或自评 PASS 代替实际检验。每个关键问题至少连续追查两层，并在 G4 增补新证据或真实缺口。关键数字用可复算公式；每项引用必须可追溯、不能使用截点后信息。G5 必须通过六域各四项专项成果检查和六条跨域联动模型检查，定量成果必须有计算或真实缺口，只有G0已明确排除且不属于活跃域受保护成果的不相关项才可标 out_of_scope。

最后执行 verify。只有 COMPLETE 才能称已完整验收；存在真实重大缺口则 PARTIAL，未走完则 IN_PROGRESS，封存资料变动则 STALE 并回退。小问题可缩小范围但不得跳过关卡；关键问题不能故意降为非关键。无授权不下单。研究员自行推进，不等用户逐关批准。Skill 维护、普通问答、阅读已有报告不需要创建研究任务。

若运行环境不能访问该目录或不能执行检查器，只可提供明确标注的未验收研究结果，不得宣称已完整运行 ANALYZE。检查器仅证明结构、数值复算和本地完整性，不替代原件真实性与研究判断。参考学习来源见 references/workflow-method-sources.md。

## 任务

像阅读招股书的独立研究员一样，拿原始数据把一个问题追到底，得出可复算、可检验、可用于决策的结论。不得把行业概览、新闻摘抄、通用 SWOT 或指标罗列当成研究完成。

用户给出的题目、链接和观点是研究起点。先找最能影响决策的事实，然后沿异常值、现金流、合同、控制权、供需及预期差继续追踪。目标不是证明用户或市场的观点正确，而是弄清哪些条件成立、为什么、影响多大、何时失效。

## 选择主研究入口（所有正式任务自动联动六域）

| 输入 | 先读 | 必须回答 |
|---|---|---|
| 行业、赛道、产业链 | references/playbooks/industry.md | 价值在哪产生，利润流向谁，供需为何改变 |
| 公司、股票、IPO、财报 | references/playbooks/company.md | 真实赚钱机制、成本/现金/承诺、控制权与价格隐含条件 |
| 产品、商业机会、竞品 | references/playbooks/product.md | 用户购买的究竟是什么、替代方案和经济账 |
| 政策、监管、法案 | references/playbooks/policy.md | 法律效力、执行能力、激励变化、直接及间接受影响者 |
| 市场、金融品种、BTC、区域供需 | references/playbooks/market.md | 交易结构、边际买卖方、价格形成与可重复规律 |
| 事件预期、财报、IPO定价、利率 | references/playbooks/expectation.md | 共识、已经计入价格的预期、预期差与兑现路径 |

必读：references/metric-intelligence.md（跨领域指标、定义、计算、失真机制、联合判读与下一层证据）。参考视频拆解见 references/video-method.md、references/video-case-lessons.md；数据与报告模板见 references/evidence-and-output.md。

## V5 跨域联动硬要求
所有正式研究在 init 时自动生成六域。--routes 仅指定主入口，不得用于跳过关联研究。G0 必须写清六域对象和实际关联，核心域不得 screened；非核心仅在原始证据支持影响不重要时可 screened。具体规则见 references/cross-domain.md。
研究股票必须穿透产品需求、竞争/供应链、公司现金流与资本配置、政策影响、市场定价及预期差。G1 每个原始证据按真实主题标注 topics；G2 活跃域都有指标知识卡。G4 必填 L1–L6 的两端证据、机制、时滞、条件、反证；G5 定量链接的计算必须真正引用两端原始证据的变量链；G6 逐链接复查；G7 综合模型必须把跨域计算/约束用于核心回答，并写机会成本、风险边界。无证据不得假装无影响，重大缺口只可 PARTIAL。
必读 references/expert-learning.md 与 references/cross-domain.md；按对象读 references/specialists/ 中的专业手册（八个文件，路由见 cross-domain.md），再补充陌生行业的原件、标准和实际案例。未读专业知识不能以报告术语代替，指标卡必须解释真实意义。
已有 V4 任务可继续原版本核验；V4 回执不能宣称 V5 完成。新任务一律使用 V5。

## V6 知识终版：五类信源与专业路由（强制执行）
V6 扩充研究方法和信源知识库，验收 schema 仍为 5，八关及六域联动检查器不变，既有 V5 研究可继续。
G0 后、G1 前必须读取 references/knowledge/field-intelligence.md、references/knowledge/advanced-index.md，并执行：
    python scripts\source_plan.py --routes company,industry --focus valuation,technology
将例子换成真实主入口与相关主题；可用 --output research/<ID>/sources/v6_source_plan.json 保存新计划。按结果读适用进阶手册，尤其对专业指标、风险或真实机制不熟悉时必须先学习，再进入 G1/G2。计划仅是来源导航，不是证据，不强制浏览无关信源或重复查已掌握的内容。
references/knowledge/source_registry.json 和 source-atlas.md 记录本轮55条入口（X、YouTube、博客、官方信、GitHub等）及实际阅读程度、用途、局限。X 查消息起点/专家异议，YouTube 学机制，博客学模型，官方信查承诺与资金配置，GitHub 查实现和复现；结论必须回到当期一手数据及原件。已获取字幕不等于已读全文；不能把旧观点、开源项目自述或转发升级为验证事实。
G4 线索回溯两层并传到六域，G5 将实际变量用于量化联动，G6 复查原件、口径、时点、独立性、最强反证，G7 写失效条件。可用 scripts/advanced_finance_math.py 的透明公式复算并把输入来源记录入 C。新增 SVB、ASML 历史真实切片仅供学习，不是完整八关研究或投资证明。

## 金融研究专项路由（V3 保留）

- 研究公司、股票、IPO、财报、基本面和估值：额外读取 references/finance/institutional-research.md；建立三表/收入利润驱动、财务异常与合同期限、旧模型和新模型的差异、反向估值与研究观点跟踪。
- 研究利率、宏观、政策冲击、汇率、市场或加密资产：额外读取 references/finance/macro-market.md；区分原始发布值、事后修订、当前市场价格和独立情景，建传导链并查反证。
- 取证前查 references/finance/source-library.md；优先监管、公司、交易所与统计原件。金融计算优先使用可复算公式或 scripts/finance_math.py；数据、参数和结果需分开保存，脚本不是数据源。
- 视频学习先读 references/video/caption-workflow.md；默认直接获取已有字幕，使用 references/video/fetch_captions.py，未获得字幕不冒充已阅读；未经另行需要不下载媒体、不运行语音识别。
- 学习外部知识时，以可验证研究方法、指标真实含义、经济机制和能改变判断的证据为主。拒绝未经验证的荐股、自动评分与收益宣传。既有研究按新证据更新假设而非覆盖历史版本。

## 研究方法细则（为八关提供具体调查方法，不得替代关卡）

### 0. 写下研究合约
明确对象、定义、地区、时间截点、投资/经营/交易决策、决策期限。把大题拆成至多几个可行动的关键问题，例如“上市价格对应怎样的收入、利润率和融资需求？” 对象有多个名称时先确认实体、ticker、币对、交易所、产品版本、政策编号。历史研究锁定当时可获取的信息；不得拿未来公布数据回填。

### 1. 先拿原件
优先直接获得公司招股书/财报/附注/合同、监管数据库、政府原文/预算、交易所原始数据、官方产品价格和条款。保留发布日期、统计期间、生效日、URL、页码/表名/字段、抓取时间与单位。可合法获取的文件放入本次研究目录 sources/。新闻、视频、社群和研报用来找到线索、对照共识和发现反例，不直接替代原件。搜索中文及原文语言，必要时使用 PDF 搜索、目录、脚注、文本提取与表格读取。原件无法获得就明确缺口，不编造页码、数字或链接。

### 2. 制作可复算的数据底表
把至少覆盖关键变化的历史期间、基准对象、同口径竞品列在同一张表，保留原始值、单位、定义和派生公式。将实际收入、ARR/run-rate、预测收入、净利润、经营利润、经营现金流、自由现金流、融资流入分别记录。政策草案与正式法律、名义值与实际值、交易量与成交额、期末存量与期间流量分别记录。图表展示趋势时要能返回原始表。

### 2.5. 指标穿透：遇到指标就追问含义
先按 metric-intelligence.md 的六问建立指标卡：真实测量对象、分子分母、驱动量、正反解释、区分证据、传导和更新条件。遇到陌生术语须查原始定义、单位及适用边界，并按具体研究对象补充；不用术语装饰报告。优先寻找能区分解释的指标组合。技术指标必须回到物理约束、工况、真实交付和成本；产品指标回到高频场景、用户支付行为和替代方案；政策指标回到真实执行者、预算、受益者与承担成本的人。

### 3. 找异常，不要平均用力
寻找同一时期的反常：营收涨而毛利/经营利润跌；利润涨现金跌；销量涨单价跌；客户留存强却合同收入弱；需求强而供应商赚走利润；资产价格与消息方向相反。每个异常形成一条问题链：
**观察 → 可能解释 A/B/C → 需要什么证据 → 找文件对应段落/字段 → 复算 → 排除解释或保留不确定性 → 下一层问题。**
优先选择能够改变结论的异常。问“为什么在这里发生”“谁收钱”“谁承担不可撤销风险”“如果关键变量反转会怎样”。别只复述公司管理层的解释。

### 4. 追钱、追合同、追控制权、追实际交付
画交易关系图：付款方→收款方→最终使用方；列客户、供应商、股东、债权人、政府、竞争对手的多重身份。读取合同履约、取消条款、价格调整、担保、到期支付、融资、稀释、董事任免、法律权力、许可等与问题有关的条款。比较同期限同口径的确定收入、固定支付和现金来源；检查条件是否可兑现，产能是否真的上线，需求是否来自独立终端客户。不要把相关交易直接定性为造假；追踪最终外部现金和真实交付。

### 5. 建机制模型，寻找反证
将结论写成 A→B→C，逐段说明可观测指标、预期方向、作用时滞、适用条件、替代解释和反例。用历史/横向案例或样本外检验验证适用部分，优先结构相似而非只看行业名字相似。没有直接因果证据时标为机制假设。若研究结论相反时也会使用同一组事实，说明证据区分力不足，继续追查。

### 6. 把故事变成数字，把价格反推成条件
按对象建立合适的模型（收入拆分、单位经济、供需缺口、现金缺口、政策受益规模、事件情景、估值敏感性等）。记录参数来源。至少比较基准、上行、下行，必要时增加压力情景。反算市场价格/目标收益需要的收入、增长、利润率、估值倍数、现金流或事件概率；再与产能、客户预算、历史及竞品的可实现范围比较。不要用任意精确概率掩盖未知。

### 7. 给出可更新的判断
先回答研究问题，再提供证据链、核心数字、情景、关键未知、验证指标、什么信息会改变判断以及下一次更新条件。投资价值与短期价格交易分别分析；研究输出不自动下单，不执行用户未授权的资金操作。若数据不足，交付实际完成部分、关键缺口及最优下一步，而非填空或宣布确定结论。

## 文件约定

由检查器 init 生成 research/<ASCII任务ID>/ 中的 manifest.json、00_scope.json 至 07_decision.json、report.md、sources/、data/、analysis/、_gate/、_history/。各关 JSON 为权威记录；evidence.csv、assumptions.csv 可按需导出，不取代关卡。完整结果以 completion.json 与 verify 为准。已有研究先 status，修改已通过阶段用 rewind，保留旧版本/截点。辅助表格见 references/evidence-and-output.md。不要在研究目录保存 API 私钥、账户凭据；公共接口优先，必要的已授权接口仅用最小权限。

## 完成条件

必须先通过八关并运行 verify（如有重大缺口只可交付 PARTIAL）。研究必须有清晰的对象与问题、可追溯证据、至少一条真正推导的经济/因果机制、与核心结论对应的量化模型或明确的量化缺口、反面证据、失效条件及可执行的下一步。规模按任务决定：小问题可精简调查重点，但六域关联与六条链接须按 V5 验收；重大决策深挖全部实质相关域。不得用搜索次数、报告字数或重复检查替代证据质量。以大白话报告，专业指标首次出现解释其分子、分母、含义、为什么变动、其他可能解释及下一步验证证据。每项关键判断至少具备一个明确的现实机制与区分证据。
