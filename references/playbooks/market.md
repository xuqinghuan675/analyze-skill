# 市场研究｜谁在边际上定价，规律何时有效

1. 定义市场边界：标的/产品、交易所、现货或衍生品、币种和单位、地区/时间、交易期限。读取交易所合约规格、交易规则、费用、保证金、撮合及数据字段；实体商品查统计/采购/批发数据。时间戳统一 UTC，展示按用户时区；区分实时和延迟数据。
2. 先获取原始序列。金融市场用交易所官方 API、官方历史数据、监管统计（例如 CFTC COT、FRED 的宏观数据按对象使用）。BTC 可用 OKX API 文档核对当前接口：/api/v5/public/instruments、/api/v5/market/history-candles、/api/v5/market/books、/api/v5/market/trades、/api/v5/public/open-interest、/api/v5/public/funding-rate-history 等；WebSocket 盘口和成交需持续采集并处理序号、断线、快照/增量，具体可用字段与权限现场验证。仅凭 K 线不能还原历史盘口；不虚构缺失数据。
3. 描述价格形成：成交方向、深度、买卖价差、成交量、订单流失衡、持仓、资金费率、基差、波动率、强平数据可得性。链上与宏观/新闻作为外部变量；区别成交、持仓、转账和净买入。实体市场用订单、库存、交付、可替代供给、合同价与现货价。
4. 识别当前状态：用明确可测的特征（趋势、波动、流动性、价格位置、期限结构、资金拥挤）而非主观涨跌形容；按历史滚动分位数或训练期阈值划分，不能用未来数据标注交易时可知状态。解释当前边际买家/卖家变化的证据。
5. 观察异常并提出假设：例如订单流失衡领先短时价格变化、资金费率和持仓同时增长后行情脆弱。写清信号定义、方向、时间窗口、经济机制、适用状态、替代解释、交易成本和执行延迟。先看事件研究/条件收益分布、样本数、基准收益，检查多重尝试与偶然性；不是先调参找最赚钱组合。
6. 验证：按时间切分发现/验证/最终留出；走步检验、适当隔离重叠标签、交易费/资金费率/滑点/撮合延迟和可成交量；对照无信号及简单基线，按行情状态、时间段拆净收益、回撤、交易频率、置信区间（时序相关用合理的 block bootstrap 等）；记录尝试过的假设与失败结果。迁移到另一市场时先检验机制与规则是否相似。
7. 建策略生命周期：上线前设成本后优势阈值、最大回撤/连续亏损或滚动绩效监测条件、数据完整性、停止/降风险/重新验证条件。阈值源自历史和用户风险预算，预先锁定；适应市场变化通过重新估计状态/参数和独立验证完成，不能不断用已失效结果拟合。交易研究仅输出信号、规则、触发条件、风险与验证结果，未经授权不下单。

交付：源数据及口径、市场参与者和定价机制、状态诊断、可检验假设及验证表、当下观察与失效条件。研究市场不一定需要开发策略；只研究具体价格或供需时按对应目标缩减。
