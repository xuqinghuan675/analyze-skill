# 产品研究｜还原一笔真实购买决策

1. 锁定产品版本、地区、目标用户和购买场景。以实际使用、产品文档、官方价格/套餐、服务条款、上线日志和帮助中心为起点；查询应用商店评论、GitHub issue、Reddit/论坛、售后投诉和真实用户访谈，记录样本选取偏差。
2. 建需求地图：谁用、谁决定购买、谁付款、什么时候买、原本如何完成任务、失败成本多少。分用户群体，而不是用一个平均用户替代。搜索 "<product> alternative / pricing / cancellation / review / migration / benchmark / security / limitation"。把用户说的喜欢与实际复购/付费/续约分开。
3. 实测典型任务：选定同一输入和验收标准，亲自走注册→上手→关键任务→导出→售后/取消流程（付费或操作账户需授权）。记录时间、成功率、错误/人工介入、总成本、上手和切换成本。不能实际试用就明确，以文档和可复现公开测试替代。
4. 比较解决同一任务的替代方案（包括不使用该产品、人工、自建、免费开源）：统一工作量、质量阈值、成本周期。量化用户账：原方案成本 - 新方案价格 - 迁移/维护成本；另列速度、风险和可靠性收益。用企业预算与真实使用频率评估支付意愿。
5. 追商业模型：价格×实际付费用量，订阅与按量分开。建单位经济：每客户/任务收入 - 推理/物料/配送/支付/支持等变动成本=贡献利润；固定成本另列。估 CAC、回本周期、留存与流失；LTV 只在可支持稳定留存假设时估算。根据新/老客户和渠道拆增长。
6. 查供给可扩张性：容量、外部供应商依赖、服务 SLA、迭代成本、关键技术/数据/渠道、合规。评估边际成本是否随使用增长、单价是否随竞争下降。检验可复制性、切换成本和网络效应，而不是从功能多推断护城河。
7. 找未满足需求：高频差评/手工工作流/被迫高价的场景→访谈验证→小范围需求实验→支付或留存验证。产品机会用低成本实验、明确成功指标和停止条件收尾。若为了公司投资研究，回填该产品的收入贡献和增长上限。

交付：用户-任务-付费链、实测记录与竞品同口径表、用户 ROI 和供应方单位经济、优势/缺口及验证计划。
